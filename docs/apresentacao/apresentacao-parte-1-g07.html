Arquiteturag07 · EDA262 · Parte 1

Granularidade: uma linha por CVE

  • Grão declarado no próprio catálogo, como parâmetro da tabela: grain = "one row per cve_id"
  • Provado, não afirmado: uma named query roda count(*) − count(DISTINCT cve_id) e precisa retornar 0.
  • Alternativa avaliada e descartada com número: um grão por (CVE, produto).
  • 214 de 1.710 valores de product (12,5%) trazem separador ambíguo.
"NetScaler ADC and NetScaler Gateway" → 2 produtos "Community Edition and Enterprise Edition" → 1 produto

Nenhuma regra determinística separa os dois casos. Dividir pelo separador inflaria a contagem de produtos por artefato de parsing — no indicador que a pergunta mede.

Decisão 2 · qualidadeg07 · EDA262 · Parte 1

Schema declarado em código, sem Crawler

  • As 15 colunas são declaradas em Terraform e renderizadas a partir de uma única fonte de verdade.
  • Um Crawler custa USD 0,073 por execução (USD 0,44/DPU-hora, mínimo de 10 min — preço de tabela).
  • Sobre um schema estável, ele pagaria para redescobrir o que já sabemos — e poderia variar o tipo entre execuções.
  • Schema como código custa USD 0,00, entra em code review e falha no plan, não em produção.
columns = [ { cve_id string } { vendor_project string } { product string } { date_added string } { is_known_ransomware_use boolean } { requires_forensic_triage boolean } { cwes array<string> } { cwe_count int } { catalog_version string } { ingested_at string } ... ]

Datas ficam string em ISO-8601: em NDJSON todo valor é texto, e forçar date transformaria falha de parsing em NULL silencioso — justamente no filtro de 12 meses.

Por que não usamos Parquet
  • O dataset inteiro cabe 7 vezes dentro do mínimo cobrável de 10 MB.
  • Parquet, particionamento e compressão reduziriam os bytes lidos...
  • ...e nenhum centavo da fatura: a cobrança já está no piso.

Decisão 4 · custog07 · EDA262 · Parte 1

Disciplina de infraestrutura

  • Módulo + backend remoto + workspace. O workspace av1 gera os nomes exigidos; outros recebem sufixo, porque nome de bucket S3 é global.
  • O workspace default é bloqueado por precondition: falha no plan, antes de criar qualquer recurso.
  • O SQL mora no Terraform como named query, e o script a executa por ID — o que roda não pode divergir do que foi revisado.
  • Destroy é verificado, não presumido: o Terraform retorna sucesso mesmo deixando órfão. Conferimos os 5 recursos na AWS depois.
