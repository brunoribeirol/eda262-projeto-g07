Architectureg07 · EDA262 · Part 1

Grain: one row per CVE

  • The grain is declared in the catalog itself, as a table parameter: grain = "one row per cve_id"
  • Proven, not asserted: a named query runs count(*) − count(DISTINCT cve_id) and must return 0.
  • Alternative evaluated and rejected with a number: a grain per (CVE, product).
  • 214 of 1,713 product values (12.5%) carry an ambiguous separator.
"NetScaler ADC and NetScaler Gateway" → 2 products "Community Edition and Enterprise Edition" → 1 product

No deterministic rule separates the two cases. Splitting on the separator would inflate the product count through a parsing artifact — in the very indicator the question measures.

Decision 2 · qualityg07 · EDA262 · Part 1

Schema declared in code, no Crawler

  • The 15 columns are declared in Terraform and rendered from a single source of truth.
  • A Crawler costs USD 0.073 per run (USD 0.44/DPU-hour, 10-minute minimum — list price).
  • Against a stable schema it would pay to rediscover what we already know — and could drift types between runs.
  • Schema as code costs USD 0.00, goes through code review, and fails at plan, not in production.
columns = [ { cve_id string } { vendor_project string } { product string } { date_added string } { is_known_ransomware_use boolean } { requires_forensic_triage boolean } { cwes array<string> } { cwe_count int } { catalog_version string } { ingested_at string } ... ]

Dates stay string in ISO-8601: in NDJSON every value is text, and forcing date would turn a parse failure into a silent NULL — precisely in the 12-month filter.

Why we did not use Parquet
  • The query scans 3.0 MB and fits 3.5x inside the 10 MB minimum billing unit.
  • The scan is 2.00x the table: the scalar subquery makes Athena read the data twice — only found by measuring.
  • Parquet and partitioning would cut bytes read — and not one cent of the bill, which is already at the floor.
  • Measured saving from the optimization: USD 0.00.
  • It belongs to Part 2, once volume clears the floor — a decision by number, not by calendar.
Decision 4 · costg07 · EDA262 · Part 1

Infrastructure discipline

  • Module + remote backend + workspace. The av1 workspace produces the mandated names; others get a suffix, because S3 bucket names are global.
  • The default workspace is blocked by a precondition: it fails at plan, before creating any resource.
  • The SQL lives in Terraform as a named query, and the script runs it by ID — what executes cannot drift from what was reviewed.
  • Teardown is verified, not assumed: Terraform reports success even when it orphans a resource. We re-check all 5 against AWS afterwards.
